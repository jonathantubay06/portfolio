How I push 200 price changes without breaking a store

Shopify · Cin7 Core · Python

A US tools retailer got new supplier prices every week. Someone typed them into Cin7 Core and then into Shopify, across thousands of SKUs. One typo could put a product below the supplier's minimum advertised price.

So the price list became the only input. Python and Playwright scripts clean it up and apply the pricing rules, then stage a batch of about 200 SKUs in Cin7. The batch gets checked for price, MAP and shipping dimensions. Only then does it go to Shopify, and it lands as drafts, so a person signs off before customers see anything.

Small batches matter more than the scripts. When something is wrong, it is wrong in 200 rows, not 5,000, and it is caught before it is public. The team saves 10+ hours a week. Full case study →

A business website in three weeks, solo

WordPress · Discovery first

MOEV Solutions installs EV chargers in the Philippines. They had no developer and needed to be live in weeks. Three kinds of visitor mattered: fleet operators, homeowners and maintenance partners.

Before writing code I mapped their four service lines, Supply, Installation, Maintenance and Consultation, to pages, so each visitor had one clear path. The theme was custom with no page builder: less to load, and less for a team without a developer to maintain. Every page was designed phone-first, because that is where fleet managers and homeowners read it.

Most of the speed came from that first day of mapping. Once the structure was right, the build was mostly filling it in. Full case study →

A 3D room on desktop, pictures on phones

This site · Performance

This site opens on a 3D desk you can explore on a desktop. On a phone the same experience would drain the battery and load slowly, so phones get pre-rendered pictures of the same scenes behind the page instead of live WebGL.

The code is split the same way. Everything that only the desktop uses, the 3D desk, the room and the moving logo row, lives in its own file that phones never download, about 144 KB they skip. Both versions still have to pass the same readability check: every line of text at least 4.5:1 contrast, on phone and desktop, in dark and light mode.

The rule I keep coming back to: rich where the device can afford it, simple where it can't, and readable everywhere.
