# Incident response: jonathantubay.com

Owner: Jojo (personal). Written 2026-10-24. Use this if the site shows something you did not publish, the domain or an account looks taken over, or a secret leaks.

## 1. Stop the damage (first 10 minutes)

1. **Roll the site back.** Netlify > the site > Deploys > pick the last good deploy > "Publish deploy". Then "Lock to stop auto publishing" so a new push cannot replace it.
2. **Check the domain.** Namecheap > Domain List > jonathantubay.com: nameservers must still be Netlify's (dns1-4.p0x.netlifydns.*), transfer lock on. Netlify > Domains > DNS records: nothing you did not add.
3. **Check GitHub.** Repo > Settings > Collaborators, Deploy keys, Webhooks, Actions secrets: nothing unknown. Commits on `main` you did not make: note their hashes.

## 2. Lock the accounts

Change the password and sign out all other sessions, in this order: email (Gmail), GitHub, Netlify, Namecheap, Cloudflare. Then:

- GitHub > Settings > Developer settings: revoke every personal access token and OAuth app you do not recognise.
- Netlify > User settings > Applications: revoke personal access tokens.
- Re-check 2FA is on everywhere (passkey or authenticator app, not SMS) and that recovery codes are yours.

## 3. Clean up

- Revert the bad commits on `main` (`git revert <hash>`), build locally (`node build.js`), check, push. Unlock publishing in Netlify.
- If a secret was ever committed: rotate it at the provider first. Removing it from git history does not un-leak it.
- Contact form (Netlify Forms + Netlify's reCAPTCHA): if spam floods it, Netlify > Forms > the form > delete spam and check the notification email is still yours.

## 4. Afterwards

- Write what happened, when, and the fix in `history/YYYY-MM-DD.md`.
- `.well-known/security.txt` lists the contact address for outside reports; renew its `Expires` date yearly (current: 2027-10-24).

## What protects the site today

- Static files only (no server code, no database). Netlify publishes `dist/` only.
- Strict Content-Security-Policy generated by `build.js` into `dist/_headers`: inline scripts allowed only by sha256 hash, no third-party script hosts except Cloudflare analytics and reCAPTCHA. The build fails if an inline `on...=` handler is added.
- three.js is self-hosted in `vendor/` (no jsDelivr at runtime).
- GitHub Actions pinned by commit SHA, read-only token, Dependabot for action updates.
