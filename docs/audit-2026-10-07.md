# jonathantubay.com audit (2026-10-07, read-only)

Nothing in the project was changed. All evidence lives in this folder:
- `lh-mobile.json`, `lh-desktop.json`: Lighthouse 12 runs on the live site
- `shots/*.png`: device-shots `--full` (9 profiles). Note: WebKit full-page shots show blank areas below the hero because scroll-reveal never fires in a full-page capture. Use `mob/*` for what users actually see.
- `mob/*`: WebKit iPhone SE (light and dark) and iPad Mini (dark), captured one viewport at a time while scrolling. Sheets: `mob/se-light-sheet.png`, `mob/se-dark-sheet.png`, `mob/ipad-sheet.png`
- `d3/*`: 1440 and 1920 Chromium using **SwiftShader**, i.e. software WebGL, which behaves like a PC with no usable GPU. Load sequence, scroll frames and `*-perf.json`
- `gpu/*`: 1440x900 at DPR 2 on the **real RX 9060 XT (D3D11)**. Load sequence `seq-*`, `hero-settled.png`, `hero-cta-hover.png`, `before*.png`, scroll frames, `perf.json`, and sheets `sheetA.png`/`sheetB.png`
- `assets/*`: zoomed crops for each 3D asset (listed in section 3)
- `fx.js`, `index.html`: copies of the live bundle used for the line references

Severity scale: **C** critical, **H** high, **M** med, **L** low, **N** nit.

## 0. Top 10 (do these first)

1. **H, perf/3D.** Desktop TBT is 690 ms and Lighthouse desktop Performance is 61. On a strong GPU the hero idles at 47 fps and scrolls at 24 fps, with frames up to 133 ms. On software GL it runs at 2-3 fps with 300-500 ms tasks every frame and never backs off.
2. **H, perf.** `scene.glb` is fetched and parsed twice, once by the hero (36-hero-3d.js:178) and once by Contact Dumpling (39-section-3d.js:281).
3. **H, look.** The desktop hero first paints `hero-plate-720w.webp`, a photo-real AI render (desktop LCP element), then swaps to the toy-style WebGL desk at about 2-4 s. The style jump is very visible (`d3/1440-load-02` vs `-13`, `gpu/seq-0` vs `seq-4`).
4. **H, look.** The hero 3D is too busy and competes with the headline. The giant gold/blue gear, the magenta dusk "skyline" and about 25 props all fight for attention (`assets/00-hero-full-settled.png`).
5. **H, look.** The photo cut-out dogs clash in style with the low-poly scene and have weak grounding. They are billboards, which is exactly the "still image" the user does not want (`assets/dogs-front.png`).
6. **H, bug (WebKit).** Buttons render in a serif fallback font on iPhone/iPad, e.g. "DETAILS" and "See Deirdre P. Malcolm Art" (`mob/se-light-sheet.png` row 2). There is no global `button{font:inherit}`.
7. **H, tablet.** On iPad the "SCROLL TO EXPLORE" pill covers the stat strip (`assets/ipad-hero-bottom.png`). The keyboard-shortcut hint ("Press H Home…") also appears on a touch device and covers card text (`assets/ipad-hint-bar.png`).
8. **M, mobile perf.** Mobile LCP is 4.7 s (Performance 78). The LCP element is the "Jonathan" `span.glow`, and 1.76 s of that is *render delay*, caused by the glitch/scramble intro hiding the text.
9. **M, links.** All 5 `verify.skilljar.com/c/...` certificate links return 404 to a scripted GET. Check them by hand in a browser. If they are dead, the Certifications tab is showing broken proof.
10. **M, look.** The laptop, which is the focal object, shows a pastel placeholder page instead of real work. The ops dashboard and code card textures are too low-res to read at DPR 2.

### 1.3 Findings
- **H** Two scene.glb loads. Hero 36-hero-3d.js:178 and Contact dog 39-section-3d.js:281 each call `loader.load('img/hero3d/scene.glb')`. The network log shows 2x 200, and the 780 ms long task at 4.1 s is parse/upload. **Fix:** expose `window.__hero3d.gltf` as a Promise and `SkeletonUtils.clone` / `.clone(true)` the dog group in 39-section-3d.js. Saves one parse and up to 445K on a cold cache.
- **H** Hero renders every frame at DPR 2 with MSAA plus UnrealBloom (36-hero-3d.js:92-93, 113). The canvas was 1950x1674 backing pixels on a 1440 window. **Fix:** `setPixelRatio(Math.min(devicePixelRatio,1.5))`, and add an adaptive governor: measure the average frame time over 2 s; if above 22 ms drop to DPR 1 and skip bloom; if still above 30 ms, stop the loop and show the static poster.
- **H** No low-end or software-GL guard. On SwiftShader it runs at 3 fps forever (`d3/*-perf.json`: 400+ long tasks of 300-500 ms). **Fix:** create the renderer with `failIfMajorPerformanceCaveat:true`, and check `UNMASKED_RENDERER` for /SwiftShader|llvmpipe|Basic Render/. Plus the governor above.
- **M** The hero loop never idles. It runs continuously while visible, including when nothing changes. Consider about 30 fps when idle (no pointer move for 3 s) by rendering every other rAF.
- **M** Pointer and scroll smoothing is per-frame, not time-based (`px += (tx-px)*0.05`, `sp`, `mood`, around 36-hero-3d.js:755-760), so feel changes between 60, 144 and 30 Hz. Use `k = 1-Math.pow(1-0.05, dt*60)`.
- **M** Forced reflow of 464 ms on desktop is attributed near fx.js:729, the tech-marquee `frame()` (29-tech-marquee-3d.js) reading `window.scrollY` after other rAF writers have set transforms. Cache scrollY in a passive scroll listener (as the hero already does) and read only that.
- **M** Mobile LCP render delay of 1.76 s. The h1 glow span is hidden or scrambled by 01-1-text-scramble / glitch until JS runs. **Fix:** render the final name in HTML and have JS only add the effect class after `requestIdleCallback`, or skip the scramble on mobile.
- **M** `hero-plate-720w.webp` (37K) is downloaded and painted on desktop, then hidden. That is fine as an LCP placeholder, but see the 3D section for the style mismatch. Alternatively ship a poster rendered **from the same GLB** (a Blender render of build_scene at the hero camera, about 40K webp) so the swap is invisible.
- **L** Two RUM scripts: Cloudflare beacon (10K, legacy JS, short cache, flagged by Lighthouse) plus Netlify RUM. Keep one.
- **L** Unused JS 83K (mostly three core, unavoidable without a custom build) and unused CSS ~21K. The CSS is 30 layered pass files (`36-enhancement-passes`, `52-banger`, `53-round4`, `57-audit-fixes`…). Consolidating them would cut the overrides and the unused rules.
- **L** jsDelivr is a third-party origin for 7 ESM modules, so each one needs a DNS/TLS handshake plus waterfalling. Add `<link rel="preconnect" href="https://cdn.jsdelivr.net" crossorigin>` gated to desktop, or self-host one bundled `three-hero.js` (about 190K, immutable-cached on Netlify).
- **L** HTML is `Cache-Control: max-age=0,must-revalidate` (fine). There are **no security headers** besides HSTS: add CSP, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` and `Permissions-Policy` in netlify.toml.
- **N** `favicon.ico` 404s. Browsers still request it, so add a redirect or file. There is no web manifest (`manifest.webmanifest` 404), which is optional.
- **N** Lighthouse "image-delivery": logo-ring.webp and logo-dial.webp are larger than displayed (about 14K savings).

### 3.5 Real 3D dogs: options and recommendation
1. **Stylised low-poly rigged dogs with fur cards (recommended).** One CC0 quadruped base (Quaternius "Ultimate Animated Animals" Shiba/Husky or the Poly Pizza CC0 dog, already rigged with idle, sit and wag clips) remodelled in Blender per dog for proportions: Mochi bigger with a long snout and tan/white patches, Tofu cream with fold ears, Pochi short with black/white head patches lying down, Dumpling fluffy poodle-mix with alpha fur cards on ears, tail and chest. Hand-paint the albedo by projecting each dog's photo from the front view (Blender "Project from View", then clean up). This matches the low-poly desk, gives real lighting and turning, and keeps likeness through colour pattern and silhouette. **~60-100K per dog with meshopt, 4 dogs ≈ 300-400K.** Effort 2-4 days. Risk: medium, because likeness depends on the patch painting.
2. **Photogrammetry-style.** Project the photos onto a sculpted mesh. Best likeness from one angle, but it breaks as soon as the camera leans and textures smear on turned surfaces. Not recommended for the moving camera.
3. **Keep billboards, upgrade them to 2.5D.** Normal map + depth-offset parallax from each photo (Depth Anything), lit by scene lights, camera yaw clamped to ±10°. Low weight (+80K) and 1 day. It still reads as cut-outs when the camera leans.
4. **AI image-to-3D** (TripoSR / Hunyuan3D-2 locally on the RX 9060 XT): fast mesh from the photo, but topology and fur come out blobby and need retopo plus rigging anyway. Use it only as a sculpt reference for option 1.

**Recommendation:** option 1, with option 3 as a stopgap this week if time is short. Load the dogs as a separate `dogs.glb` after the desk (progressive) so the hero appears sooner.

## 5. Effects JS code quality
- **H** Duplicate GLB parse (1.3).
- **M** 36-hero-3d.js has no `webglcontextlost` handler and no dispose path. If the desktop gate stops matching (window resized below 1024 or reduced-motion toggled), the renderer, composer and bloom targets keep their memory, and the loop keeps running while the canvas is hidden by CSS. **Fix:** `ok.addEventListener('change', …)` → stop the loop, `renderer.dispose()`, `composer.dispose()`, traverse and dispose geometries, materials and textures, then `renderer.forceContextLoss()`. The same applies to 39-section-3d.js (shared low-power renderer, no context-lost handler).
- **M** The gate is evaluated once at load (36-hero-3d.js:37-38; 40-desk-extras.js:19 caches `.matches`). Growing a window from 900 to 1440 never starts the 3D. Listen for `change` and boot lazily.
- **M** 37-live-wallpaper.js does this well (pause on hidden, context-lost teardown, gate listener). Use it as the template for the other two.
- **L** Many global `addEventListener('scroll'|'resize'|'pointermove')` calls across 36/38/39/40 are never removed. That is harmless on a single page but adds up to about 10 passive scroll handlers. Use one shared scroll/pointer store (as `08-scroll-single-throttled-handler-perf.js` does for main).
- **L** Canvas text in the 3D uses `system-ui` fonts (36-hero-3d.js:364, 435), so it renders differently on Mac and Windows. Use the loaded Plus Jakarta (`document.fonts.ready` first).
- **L** The CDN import failure path silently keeps the plate. That is good, but log it once (`console.info`) for debugging.
- **N** effects.js ships unminified line breaks (Lighthouse: 6K saving). Run it through the existing minify.js.
