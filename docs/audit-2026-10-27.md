## Executive summary: what to fix

1. **Google reCAPTCHA loads on every visit** (about 420 KB, a 350 KB script, an iframe, a Roboto font and a web worker). It starts at 0.7 s, alongside the CSS and fonts, which slows the mobile first paint. Netlify adds `<script src='https://www.google.com/recaptcha/api.js'>` to the page when it deploys, because the form has `data-netlify-recaptcha`, so the page code cannot delay it. Pick one:
   - **A (simplest):** remove reCAPTCHA. Keep the honeypot, Netlify's own spam filter and the inline human check. All Google hosts can then leave the CSP.
   - **B (keeps a captcha):** use your own reCAPTCHA v2 keys, set in Netlify as `SITE_RECAPTCHA_KEY` and `SITE_RECAPTCHA_SECRET`. The page then renders the widget itself and loads `api.js` only when the contact section comes near. This needs a key pair created at google.com/recaptcha/admin.
2. **Label in Name (WCAG 2.5.3):** the hero stat links read "13 Sites & Tools Shipped" on screen, but their `aria-label` says "13 sites and tools shipped, see my work". Speech-control users say the visible words, so the label must contain them. Fix: `aria-label="13 Sites & Tools Shipped, see my work"`, and the same for the reviews link.
3. **3D room models are large and served uncompressed** (desktop only). Netlify does not gzip `.glb`. `ironman.glb` is 1.2 MB and `keyboard.glb` is 650 KB; both are mostly geometry, since their textures are already small WebP. Lighthouse estimates 867 KB could be saved. Fix: `gltf-transform simplify` plus `meshopt --level high` on the heaviest props, then compare visually.
4. **Desktop main thread: TBT 750 ms**, mostly 3D setup in `effects.js` (1.37 s of scripting). LCP is still 2.1 s and CLS is 0, so the page stays usable. Optional fix: break the room build into chunks with `scheduler.yield()`, falling back to `setTimeout(0)`, between prop loads.

## Security (verified live)

Already in place, nothing to change:
- **CSP:** `script-src` allows only 'self' plus sha256 hashes for 5 inline scripts, with no `unsafe-inline` for scripts. It also sets `object-src 'none'`, `base-uri 'self'`, `form-action 'self'` and `frame-ancestors 'none'`.
- **Other headers:**
  - HSTS: `max-age=63072000; includeSubDomains; preload`.
  - X-Frame-Options: DENY.
  - X-Content-Type-Options: nosniff.
  - Referrer-Policy: strict-origin-when-cross-origin.
  - COOP: same-origin.
  - Permissions-Policy: closed for every sensor and device.
- **Form:** Netlify Forms posts to the same origin. It has a honeypot, maxlength limits (100, 254 and 5000), inline validation and reCAPTCHA. There is no custom API, so there is no CSRF surface; there are no cookies or sessions to steal.
- **XSS:** the automation demo and every other script write with `textContent` or fixed strings. URL parameters are only tested with regexes. There is no `eval` or `new Function`, and the build fails if an inline `on*=` handler is added.
- **Dependencies:** there are no npm runtime dependencies. three.js 0.170 is self-hosted in `vendor/`, built in the WSL sandbox. GitHub Actions are pinned by SHA with a read-only token, and Dependabot (actions), secret scanning and push protection are all on.
- **Domain and email:** SPF `-all`, DMARC `p=reject`, CAA set to Let's Encrypt, and `security.txt` until 2027-10-24.

Notes:
- The email and phone number are deliberately public.
- `style-src` keeps 'unsafe-inline', because the 3D and motion code set inline styles. This is low risk while scripts are locked.

## Performance

Done:
- AVIF images with a WebP fallback (55 files, 637 KB smaller).
- Width and height set on every image, so CLS is 0.
- Lazy images, including modal images held back until warm.
- Two self-hosted variable fonts, preloaded.
- Hashed CSS and JS with immutable caching.
- Phones get a static poster instead of three.js.
- Save-Data skips the 3D.
- Speculation-rules prefetch for the case studies.

Open, apart from items 1, 3 and 4 above:
- **Unused JS (about 230 KB):** this is `effects.js` on phones, because desktop-only code ships to everyone. A later refactor could split it into a phone and a desktop bundle. I would not do it before item 1.
- **Unused CSS (12-26 KB):** small. Skip it.
- **DOM size (2,600-2,800 elements):** it comes from the modals and the room HUD. Fine for now.
- **Third-party cache TTL:** the Cloudflare beacon and the reCAPTCHA logo are outside our control.

### Automation demo widget
`src/scripts/effects/32-automation-demo.js` is about 90 lines:
- It changes state with class toggles and draws with CSS transitions.
- It writes only with `textContent`.
- Its timers are cleared on every reset.
- One forced reflow per option click restarts an animation. This costs nothing in practice.
- Its log has `aria-live`.
- No change needed.
